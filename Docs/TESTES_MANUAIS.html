🔐 Autenticação e Segurança

Registre um usuário via POST /api/auth/register (role Cliente, Restaurante, Admin ou Entregador) e autentique-se com POST /api/auth/login para receber credenciais válidas. Os endpoints de leitura pública como /api/restaurantes, /api/produtos e /actuator/health continuam disponíveis sem login, mas todo o resto exige um cabeçalho Authorization: Basic <base64(email:senha)>.

curl -X GET "http://localhost:8080/api/pedidos" \
          -H "Authorization: Basic $(echo -n 'cliente@delivery.com:Senha123!' | base64)"

Não esqueça de usar senhas criptografadas com BCrypt e marcar o usuário como ativo no cadastro.

Grupo 1: Testes de Validação Devem Falhar

Valida regras de negócio com valores inválidos. Esperado: Status 400/422

  • CPF inválido (sequência)
  • Nome muito curto
  • Telefone muito curto
  • CNPJ inválido
  • Taxa entrega negativa
  • Preço zero
  • Preço negativo
  • Número de pedido inválido
  • Status pedido inválido
  • Quantidade zero
  • Pedido sem itens

1. Inicie a API

./mvnw spring-boot:run

2. Importe a Collection

Postman: Import → delivery-api-postman.json

Bruno: File → Import Collection → delivery-api-bruno.bru

3. Execute os Testes

Execute os grupos nesta ordem:

  1. 0 - Setup e Validação
  2. 1 - Testes de Validação
  3. 2 - Criação de Dados Base
  4. 3 - Consultas Simples
  5. 4 - Relatórios e Endpoints Complexos
